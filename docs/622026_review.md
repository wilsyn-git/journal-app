# Journal App — Usability Code Review

**Date:** 2026-06-02
**Scope:** Usability-focused review of the Next.js 16 / React 19 / Prisma journal app.
**Status:** Findings only — no code changes made.

This review catalogs usability findings across authentication & forms, navigation & layout, and the admin/rules areas. Each finding cites `file:line` and a severity (High / Med / Low). A lot of the app is already in good shape (autosave, skeletons, skip link, reduced-motion, dnd-kit keyboard support, dialog ARIA) — those strengths are noted at the end so they're preserved.

---

## Top priorities (do these first)

1. **Silent failures on the end-user Rules toggle** — a failed toggle reverts with no explanation. (High)
2. **No "unsaved changes" guard on the journal editor** — leaving the page mid-edit can lose work. (High)
3. **Inconsistent / missing confirmation on destructive admin actions** — Delete Group / Profile / Prompt / Rule delete instantly with no dialog, while Delete User / Category have proper guarded dialogs. (High)
4. **Missing keyboard focus styles across navigation** — calendar days, sidebar links, and many buttons rely on browser defaults; keyboard users lose track of focus. (High, WCAG 2.4.7)
5. **Settings profile form has no validation** — name/bio accept anything; bio is unbounded. (High)

---

## 1. End-user flows (Dashboard, Journal, Rules)

### High
- **Rules toggle fails silently** — `components/RuleCheckbox.tsx`. On a server-action error the icon just reverts (via `useTransition`) with no toast or message. The user can't tell a tap didn't register. Add error feedback + optional retry.
- **No unsaved-changes warning in the journal editor** — `components/JournalEditor.tsx`. Autosave is debounced ~1s; navigating away before the save completes loses the entry. No `beforeunload` / route-change guard. On a slow network the debounce may not flush before navigation.

### Medium
- **Save status is text-only and easy to miss** — `JournalEditor.tsx:77-85`. "Saving / Saved / Error saving" has no spinner or prominence; during fast typing the user may not register state changes.
- **Save error has no retry path** — `JournalEditor.tsx`. "Error saving" surfaces but the only recovery is re-typing to re-trigger the debounce.
- **PromptCard parses option JSON silently** — `components/PromptCard.tsx:16`. A bad options payload is swallowed by try/catch; the user sees a blank/fallback control with no signal anything failed.
- **Radio/checkbox prompts lack explicit ARIA labeling** — `PromptCard.tsx:50`. Text prompts use `aria-labelledby`; choice inputs rely only on wrapping `<label>`.

### Low
- **Past-date empty state copy says "today"** — `app/dashboard/page.tsx:215-219`. "No journal entry yet for today" shows even when viewing a past date. Reflect the actual date.
- **No required/optional indication on prompts**, and no min/max length on text answers (`PromptCard.tsx`).
- **Range-slider "ghost state"** (50% opacity until touched) is subtle and may read as disabled (`PromptCard.tsx`).
- **No focus ring on the rule checkbox button** — `RuleCheckbox.tsx`.
- **Rules page doesn't state when sections reset** — users don't know when completions clear.

## 2. Authentication & account forms

### Medium
- **Generic error messages throughout** — login, forgot-password, reset-password, settings all surface "Something went wrong" / "Update failed" with no field-level cause. Users can't tell a format error from a credential/server error.
  - `app/login/page.tsx:20`, `app/forgot-password/page.tsx:44`, `app/settings/ProfileForm.tsx:58`.
- **No client-side email format validation** — `login`, `forgot-password`. Invalid strings round-trip to the server before any feedback.
- **Password-mismatch error is not inline** — `app/reset-password/[token]/page.tsx:13-16`, `components/ChangePasswordDialog.tsx:16`. The check exists but the message appears in a top alert after submit, not beside the confirm field.
- **Timezone picker can double-submit** — `app/settings/TimezonePicker.tsx:37`. Shows "Saving…" text but the control isn't disabled during the API call; rapid clicks can fire duplicate requests.
- **Image upload gives no progress + generic errors** — `ProfileForm.tsx:20-38`. Client-side resize runs with no "processing" feedback (submit just feels slow), and failures collapse to "Failed to process image" regardless of cause (size vs format vs decode). No size limit shown up front.

### Low
- **No `autoComplete` on login email/password** — `app/login/page.tsx:11,16`. Hurts password-manager autofill. (forgot-password correctly sets `autoComplete="email"`.)
- **No autofocus on first field** — login (email), settings (name), ChangePasswordDialog. Minor friction.
- **No visual spinner on submit** — all auth buttons change text only.
- **3-second auto-redirect after reset is easy to miss** — `app/reset-password/[token]/page.tsx`. Add a visible countdown.
- **Disabled email field in settings has no explanation** — `ProfileForm.tsx:39`. Users don't know why it's locked.
- **Min-length requirement only in placeholder** — password fields show `••••••••` / "Min 6 characters" inconsistently; surface it as helper text.

### High
- **Settings profile form lacks validation** — `ProfileForm.tsx`. Name and bio have no `required` / `maxLength`; bio textarea is unbounded (no counter, no limit). Add constraints + a character counter.

## 3. Navigation, layout & information architecture

### High
- **Missing keyboard focus styles across navigation** — interactive elements lack explicit `focus:` rings and rely on browser defaults, so keyboard focus is hard to track. Notable spots: calendar day links `components/CalendarSidebar.tsx:125-157`, dashboard sidebar links `app/dashboard/page.tsx:271-291`, admin/nav links. Standardize a `focus-visible` ring token. (WCAG 2.4.7)

### Medium
- **Dashboard sidebar has no active-page indicator** — `components/DashboardShell.tsx:56-82` / `app/dashboard/page.tsx`. Write Today / My Stats / Inventory / Rules don't highlight the current page (no active class, no `aria-current="page"`). Admin sidebar does this correctly — mirror it.
- **Breadcrumbs only exist in admin** — `components/admin/AdminSidebar.tsx`. `/stats` and `/inventory` have only a back arrow; no "where am I / back to dashboard" context.
- **Inventory has no loading skeleton** — no `app/inventory/loading.tsx`, unlike dashboard/stats/admin. Add one for the streak-freeze/shield items.
- **Mobile section context is thin on Stats** — `app/stats/page.tsx:69-76`. Header shows a title + back arrow but no breadcrumb/IA context.

### Low
- **Mobile header can crowd on ~320px** — `DashboardShell.tsx:58-78`. Hamburger + logo + StreakBadge in one row with no `flex-shrink-0` / `truncate`; risk of overflow on small phones.
- **No desktop sidebar collapse on Stats/Inventory** — `app/stats/page.tsx:79-94`, `app/inventory/page.tsx:44-53`. Fixed `w-64` wastes space on tablets with no toggle (dashboard sidebar does toggle).
- **Sidebar sections aren't grouped semantically** — `app/dashboard/page.tsx:238-327`. Visual dividers only; wrap logical groups in `<nav aria-label="…">` for screen readers.
- **Settings gear is emoji-only** — `app/dashboard/page.tsx:242-245`. Has `sr-only` text (works) but no visible label/tooltip on desktop.
- **No "Trends" empty state** — `app/stats/page.tsx:156-168`. When trend data is empty the section just doesn't render; no "not enough data yet" message.
- **Calendar nav buttons could be more descriptive** — `CalendarSidebar.tsx:172-180`. "Previous/Next month" is fine but could name the target month.
- **No light theme / `prefers-color-scheme`** — `app/globals.css:3-36`. Dark-only by design; note for the future if light mode is ever wanted.
- **Calendar recomputes streak per day on render** — `CalendarSidebar.tsx:63-77`. `getStreakLength` walks backward for every rendered day; fine now, but memoize or precompute server-side if entry volume grows.

## 4. Admin area

### High
- **Inconsistent destructive-action protection.** Some deletes are properly guarded; others delete on a single click:
  - **Guarded (good model):** Delete User `components/admin/DeleteUserDialog.tsx` (multi-step + ack checkbox), Delete Category `components/admin/DeleteCategoryButton.tsx` (shows cascade impact).
  - **Unguarded (fix):** Delete Group `app/admin/groups/page.tsx:64-67`, Delete Profile `app/admin/profiles/page.tsx:51-54`, Delete Prompt `app/admin/prompts/page.tsx:128-135` (button only appears on hover, then deletes instantly), Delete Rule `components/admin/RulesByUser.tsx:119-126`. All are bare `form action` buttons with no confirm. Standardize on the dialog pattern.
- **Collapsible user groups missing `aria-expanded`** — `components/admin/RulesByUser.tsx:55-70`. The expand/collapse button gives screen readers no state.

### Medium
- **No success feedback on inline deletes** — Groups / Profiles / Prompts / Rules revalidate silently; the admin gets no toast confirming the delete worked (contrast with Delete User/Category which do). Pair this with the confirmation-dialog fix.
- **No loading/disabled state on inline delete buttons** — `app/admin/prompts/page.tsx:128-135`, `app/admin/groups/page.tsx:67`, `app/admin/profiles/page.tsx:54`. Slow deletes can be clicked repeatedly.
- **Users list has no search / filter / sort** — `app/admin/users/page.tsx:10-17`. Fixed `createdAt desc`, no search by name/email, no role filter, no sortable headers. Painful past ~20 users.
- **No pagination on any list** — `findMany()` with no limit/offset across users/groups/tasks/etc. Fine at current scale; a risk at 1000+ rows.
- **Reorder handle isn't labeled** — `components/admin/ReorderPromptsDialog.tsx:29-49`. dnd-kit keyboard support is present (good), but the `⋮⋮` handle has no `aria-label`, so announcements are unclear.

### Low / efficiency
- **No bulk actions** — no multi-select / bulk delete / bulk activate-deactivate on any list. Acceptable for low-volume orgs; worth it if admins manage many items.
- **No in-field error display in admin forms** — `RuleForm` / `RuleTypeForm` show errors only via toast after submit. Acceptable for short forms.
- **Rule-types and groups lists have no search** — `app/admin/rules/types/page.tsx`, `app/admin/groups/page.tsx`. Low risk unless counts grow.

## What's already good (preserve these)

- **Autosave with visible status** in the journal editor (debounced, with timestamp).
- **Loading skeletons** for dashboard / stats / admin / settings.
- **Skip-to-content link** `app/layout.tsx:63-68` and `<main id="main-content">`.
- **`prefers-reduced-motion` respected** `app/globals.css:153-163`.
- **dnd-kit keyboard sensor** for prompt reordering `ReorderPromptsDialog.tsx:56-61`.
- **Dialog ARIA** (`role="dialog"`, `aria-modal`, labelled titles, Escape-to-close) on ChangePassword/DeleteUser/Reorder dialogs.
- **Custom task checkbox** with `role="checkbox"` + `aria-checked` + keyboard handlers `components/TaskSidebar.tsx:124-149`.
- **Strong empty states** on dashboard pending-setup, stats habit-consistency, and most admin lists.
- **Consistent design tokens** — button/dialog/input styling and color palette are uniform.
- **Server-side data fetching + `next/image`** — no blocking client fetches or unoptimized images found.
- **Security-conscious copy** — forgot-password returns a generic success regardless of account existence.

---

## Suggested sequencing

**Quick wins (low effort, high impact)**
- Add error feedback to the Rules toggle.
- Fix the "today" copy on the past-date empty state.
- Add `autoComplete` + autofocus to auth forms.
- Add `aria-expanded` to the RulesByUser collapse button.
- Add an `app/inventory/loading.tsx` skeleton.

**Consistency pass**
- Standardize destructive admin actions on a confirmation dialog + success toast + disabled-while-pending.
- Add active-page state to the dashboard sidebar (match admin).
- Introduce one shared `focus-visible` ring and apply it to nav/calendar/sidebar.

**Larger / scale-driven**
- `beforeunload`/route-guard for unsaved journal edits.
- Validation + character counter on the settings profile form.
- Search/filter/sort (and eventually pagination) on the admin Users list.
