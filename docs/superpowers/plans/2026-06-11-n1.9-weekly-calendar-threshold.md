# N1.9 Weekly Calendar `'all'` Threshold Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the weekly calendar `'all'` status reachable for users with mixed weekly reset days by sizing the `'all'` threshold per reset-day group instead of against the global weekly assignment count.

**Architecture:** Single pure-function change in `lib/rules.ts:computeRuleCalendarStatus`. Capture the reset day in the weekly-key regex, precompute a `Map<resetDay, count>` of weekly assignments (normalizing `null → 0` exactly as `getPeriodKey` does), and compare each date bucket's completion count against its own reset-day group size. No schema, migration, write-path, or API change.

**Tech Stack:** TypeScript, Next.js, Vitest. Test file: `tests/lib/ruleCalendarData.test.ts` (pure in-memory unit tests against the `@internal`-exported `computeRuleCalendarStatus`).

**Spec:** `docs/superpowers/specs/2026-06-11-n1.9-weekly-calendar-all-threshold-design.md`

```typescript
  // --- Weekly: single pass over all completions to count assignments per period ---
  const weeklyStatus: Record<string, 'partial' | 'all'> = {}
  if (weeklyAssignments.length > 0) {
    const weeklyCounts = new Map<string, number>()
    for (const a of weeklyAssignments) {
      for (const c of a.completions) {
        if (WEEKLY_KEY_RE.test(c.periodKey)) {
          weeklyCounts.set(c.periodKey, (weeklyCounts.get(c.periodKey) ?? 0) + 1)
        }
      }
    }
    for (const [periodKey, count] of weeklyCounts) {
      const match = WEEKLY_KEY_RE.exec(periodKey)!
      const sundayDate = match[1]
      weeklyStatus[sundayDate] = count >= weeklyAssignments.length ? 'all' : 'partial'
    }
  }
```

with:

```typescript
  // --- Weekly: count assignments per period; threshold is per reset-day group ---
  // A weekly periodKey (week-<date>-R<resetDay>) encodes its weekday in the date,
  // so date buckets are implicitly partitioned by reset day. 'all' must therefore
  // compare against the number of weekly assignments sharing that reset day, not the
  // global weekly count — otherwise 'all' is unreachable when reset days are mixed (N1.9).
  const weeklyStatus: Record<string, 'partial' | 'all'> = {}
  if (weeklyAssignments.length > 0) {
    const weeklyGroupSizes = new Map<number, number>()
    for (const a of weeklyAssignments) {
      const resetDay = a.rule.ruleType.resetDay ?? 0
      weeklyGroupSizes.set(resetDay, (weeklyGroupSizes.get(resetDay) ?? 0) + 1)
    }
    const weeklyCounts = new Map<string, number>()
    for (const a of weeklyAssignments) {
      for (const c of a.completions) {
        if (WEEKLY_KEY_RE.test(c.periodKey)) {
          weeklyCounts.set(c.periodKey, (weeklyCounts.get(c.periodKey) ?? 0) + 1)
        }
      }
    }
    for (const [periodKey, count] of weeklyCounts) {
      const match = WEEKLY_KEY_RE.exec(periodKey)!
      const resetDate = match[1]
      const resetDay = Number(match[2])
      const groupSize = weeklyGroupSizes.get(resetDay) ?? count
      weeklyStatus[resetDate] = count >= groupSize ? 'all' : 'partial'
    }
  }
```

## Notes for the implementer

- **Do not touch the daily branch** (`lib/rules.ts:369-382`). Daily rules have no reset-day partition; its global-count threshold is already correct.
- **Behavior must stay byte-identical for the uniform-reset case.** With one reset day, `groupSize == weeklyAssignments.length`, so existing output is unchanged — the 10 original tests are the guard for this.
- **Prod safety:** this change touches no data, schema, or migration. Nothing to deploy beyond the code change. Pause for user approval before merge/deploy per the project workflow.
- **Date strings in tests** intentionally use distinct dates per reset day (`R0`/`R3`); `computeRuleCalendarStatus` does not validate weekday-vs-resetDay consistency (the existing tests already use loose dates), so exact calendar weekdays are not required for the fixtures.
